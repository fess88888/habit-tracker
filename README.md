# Habit Tracker API

Трекер привычек на стеке: Django, DRF, Celery + Redis, PostgreSQL, Docker.

## Статус инфраструктуры

Все сервисы запущены и проверены командой `celery report`:

| Сервис | Статус | Порты | Примечание |
| :--- | :--- | :--- | :--- |
| **web** | ✅ Up | 8001:8000 | Django + DRF + Swagger |
| **db** | ✅ Healthy | 5432 | PostgreSQL (volumes) |
| **redis** | ✅ Up | 6379 | Брокер сообщений |
| **worker** | ✅ Up | — | Обрабатывает задачи Celery |
| **beat** | ✅ Up | — | Планирует периодические задачи |

## Ключевые проверки (артефакты для наставника)

1. **Celery & Redis**: Проверено через `celery -A habit_tracker report`. Соединение с Redis подтверждено (`transport:redis`, `results:redis://...`).
2. **Миграции**: Все миграции применены (`showmigrations` показывает `[X]` для всех приложений).
3. **Документация**: Интерактивная документация доступна по адресу `http://localhost:8001/api/docs/`. Схема генерируется автоматически через `drf-spectacular`.
4. **Фоновые задачи**: Задача `send_telegram_reminder` настроена в админке `Django Celery Beat`. Аргументы не передаются — задача сама выбирает активные привычки.

## Тестирование и валидация

Проект покрыт юнит-тестами (`tracker/tests.py`), которые проверяют:
- Получение списка привычек с учётом пагинации DRF (`LimitOffsetPagination`).
- Создание новой привычки через API.
- Соблюдение бизнес-правил модели `Habit` (валидация в `clean()`).

**Особенности тестов:**
- Учтена пагинация DRF: ответ API парсится через `data['results']`, чтобы корректно получить список объектов.
- Соблюдены ограничения модели: в тестах не передаются конфликтующие поля (например, `reward` и `related_habit` одновременно), чтобы не вызывать `ValidationError` на этапе создания тестовых данных.
- Обязательные поля (например, `time_of_day`) всегда передаются при создании привычки.
